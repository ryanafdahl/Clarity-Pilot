# Output-only OFTEN allocation follow-up

This separate patch preserves the original RARELY-versus-all-OFTEN experiment. Apply it to a new copy of the base buffer-tools sources, never over the recorded original build.

The earlier four-run native screen found all-OFTEN slower overall, despite faster output reads. This follow-up asks whether changing only the output allocation can retain that read benefit while avoiding the input penalty. It has no established performance benefit until matched device trials complete.

The runtime change is limited to allocation usage selection. Control uses RARELY for every buffer. Candidate uses RARELY for every input and OFTEN for each output. GPU_DATA_BUFFER, public import calls, all copies/locks/fences, synchronous execution and deferred AHWB lifetime remain identical.

## Reproduce

1. Copy the current source files from the base buffer-tools package into a new directory. Omit its SOURCE_MANIFEST.json and offline-validation.json, which describe the original experiment. The follow-up SOURCE_MANIFEST.json retains the captured original and patched hashes. CURRENT_SOURCE_MANIFEST.json separately pins the current published base and patched source after the checkout-portability fix; LF-normalized hashes accommodate line-ending conversion.
2. In the copied source directory, apply this patch. The whitespace option accommodates Windows/Unix line-ending differences in the original source files.

       git apply --check --ignore-space-change /path/to/output-only.patch
       git apply --ignore-space-change /path/to/output-only.patch

3. Use the same parameterized build and tests as the base package:

       python3 build.py --kind ahwb \
         --bridge-dir /path/to/JetlinkKit/Sources/CLiteRt \
         --profiler-dir /path/to/android/tensor/profiling \
         --ndk-root /path/to/android-ndk \
         --build-dir /path/to/new/output-only-build
       python3 test.py --build-dir /path/to/new/output-only-build

The portable output binary is tensor-bench. The isolated development artifact is named tensor-bench-ahwb-output to avoid confusion with the previous all-OFTEN binary. Under the recorded toolchain they are byte-identical, SHA256 bfa13fea91af682c7786cbf11fc104bcac89c5c9d9fedaadd02141461594b633. Other toolchains may produce different binaries; use the manifest generated by your build.

## Variants and checks

Use BENCH_AHWB_USAGE=rarely for control and BENCH_AHWB_USAGE=output_often for candidate. The old selector often is deliberately rejected in this follow-up. Keep BENCH_IO_PROFILE=0 and BENCH_METRICS=1 for both initial full-frame comparisons. The original CLI, 20 warmups and all-copy requirement remain.

Every control buffer and every candidate input must report usage 16777250. Only candidate outputs must report 16777267. Confirm full NPU execution, hardware counts, health, finite outputs and byte consistency. A short smoke test precedes any longer balanced paired screen. Earlier unmatched baseline timings cannot establish an allocation effect.

Added local tests instantiate all six inputs and one output in both modes, verify each descriptor, and verify all raw buffers remain alive through wrapper/model teardown. Existing failure and copy-order tests remain. The patch applies cleanly with the documented command; portable and isolated builds match, and local I/O/AHWB tests pass. offline-validation.json records this evidence. It does not establish device performance or vehicle readiness.

The captured SOURCE_MANIFEST.json and offline-validation.json remain historical
records. Later wrapper/documentation portability changes are recorded separately
in CURRENT_SOURCE_MANIFEST.json. They do not change the native diagnostic logic;
the output-only patch is rechecked against the current base and the resulting
binary is compared with the original recorded artifact.
